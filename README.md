# AutoChoice — скелет

Подбор машины по описанию на человеческом языке + интерактивная 3D-модель (вращение, подсказки по деталям, вид из салона).

**Статус:** скелет. Вместо нейросети — захардкоженные правила (`app/nlu.py`), каталог — 20 тестовых машин,
у всех одна демо-модель `lada_vesta_parts.glb` (разбита на детали), ссылок на объявления нет.

> Миграций пока нет: при изменении колонок таблиц пересоздайте БД (`docker compose down -v`).

## Запуск

```bash
cp .env.example .env
docker compose up                # http://localhost:8000
```

Без Docker (нужен PostgreSQL):

```bash
pip install -r requirements.txt
set DATABASE_URL=postgresql+psycopg://user:pass@localhost:5432/autochoice
python wsgi.py
pytest -q
```

При старте создаются таблицы и загружается сид `data/catalog/cars.json` (идемпотентно).

## Архитектура

```
 Браузер (HTML/CSS/JS + three.js)
   │  экраны: режим → описание → вопросы → анимация → 3D + карточка → нравится / замечания
   ▼
 Flask (модульный монолит)                       PostgreSQL
   api.py ── REST /api/v1 ───────────────────▶   cars (каталог, JSONB: цвета, теги, подсказки 3D)
     │                                           sessions (анонимный профиль, версия, отвергнутые)
     ├─ nlu.py         текст → ProfileDelta      ◀── СЕЙЧАС правила, ПОТОМ наша модель (тот же контракт)
     ├─ profile.py     схема профиля (pydantic), слияние, чипы сводки
     ├─ questions.py   какой вопрос задать: max энтропии по оставшимся машинам
     └─ recommender.py жёсткий фильтр → скоринг → объяснения → контрфактуалы
   /healthz /readyz /metrics (Prometheus) · JSON-логи с request_id
 Медиа: static/media (потом S3/MinIO — меняется только MEDIA_BASE_URL)
```

### Ключевой принцип
Нейросеть (когда появится) **только переводит текст в профиль**. Машину выбирает детерминированное ядро:
одинаковый профиль + одинаковый каталог = одинаковый результат, обязательные условия не нарушаются никогда
(это проверяет тест `test_hard_constraints_never_violated`). Модель подключается заменой одной функции `nlu.parse()`.

### Поток данных
1. `POST /sessions {mode}` — новичок/эксперт.
2. `POST /sessions/{id}/describe {text}` — текст → профиль (`hard` — обязательно, `nice` — желательно с весами, `color`).
3. `GET /sessions/{id}/question` → `POST /answer` — 3 вопроса новичку, 5 эксперту; есть «свой ответ», «пропустить», «обязательно».
4. `GET /sessions/{id}/recommendation` — машина + почему подходит + компромиссы + альтернативы;
   если пусто — почему и что ослабить («поднять бюджет на 30% — подойдёт 1 модель»).
5. `POST /sessions/{id}/feedback {liked, text}` — «дороговато, хочу автомат» → профиль меняется, машина исключается, подбор заново.
6. `PATCH /sessions/{id}/profile {remove}` — снять условие крестиком на чипе.

### Экран результата
- 3D на весь экран, машина стоит на улице (`static/media/env/street.glb` из game-ready-city-buildings-pack,
  Draco + WebP, ~3 МБ; грузится сразу при открытии сайта). Всё про окружение — `ENVIRONMENT` в `viewer.js`:
  масштаб пака (×5 до метров), точка машины, стык зеркальной копии улицы (чтобы не было обрыва),
  коридор, из которого камера не выходит. Пустоту закрывают земля под сценой и дымка (`Fog`).
- **Прокрутка = экскурсия** (`TOUR` в `viewer.js`): общий вид → спереди → колёса → кузов и места → сзади →
  место водителя → управление. Ракурсы считаются от самой машины (перёд/лево/верх), а не захардкожены координатами.
- **Сноски**: у деталей шага появляются подписи рядом с деталью — короткая выноска наружу от центра машины
  (название из parts.json + факт из БД); наложения раздвигаются, закрытые детали скрываются.
  Наведение/тап на любую деталь тоже даёт сноску.
- Перетаскивание по горизонтали — осмотреться (на телефоне вертикальный свайп остаётся прокруткой).
- Весь текст (почему подходит, компромиссы, альтернативы, условия, замечание) — в шторке «Подробнее».
- Улица собрана из .blend скриптом `tools/export_street.py` (перепривязка текстур из архива, применение
  модификаторов Array/Geometry Nodes, текстуры ≤1024px, WebP + Draco):
  `blender -b --disable-autoexec CITYSKETCHFAB.blend -P tools/export_street.py -- <textures> street.glb 1024`.

### Тест на лося
- Кнопка «🦌 Тест на лося» открывает окно со слайдером скорости (30–90 км/ч) и двумя сценариями.
- **Данные — реальные, где они есть** (`REAL` в `tools/gen_catalog.py`, хранятся в `cars.specs.moose_real` / `crash_real`):
  - лосиный тест: Sportage 80, Cayenne 78, Camry 73, BMW 3 71, Octavia 70, RAV4 68 км/ч (km77, Teknikens Värld;
    часто на соседней версии — указано в подписи);
- краш-тесты: Euro NCAP, ANCAP, ARCAP, Global NCAP, ASEAN NCAP — для 14 машин.

#### 3D-ассеты и запуск подготовки

Подготовка выполняется воспроизводимо Blender 4.2 без сетевых инструментов:

```powershell
& 'C:\Program Files\Blender Foundation\Blender 4.2\blender.exe' -b --disable-autoexec `
  -P tools/prepare_moose_assets.py -- `
  'C:\Users\1\Downloads\realistic_animated_elk_3d_model.glb' `
  'C:\Users\1\Downloads\wooden_artist_mannequin.glb' `
  'app/static/media/moose'
```

`elk.glb` экспортируется через Blender в metal/rough без неподдерживаемого
`KHR_materials_pbrSpecularGlossiness` и сохраняет 53 клипа. `mannequin_rig.glb`
имеет Y-up, высоту 1,75 м и анатомические узлы. Манекен имеет лицензию
Sketchfab Standard: `mannequin_report.txt` фиксирует ограничение, поэтому
публиковать этот файл без разрешения правообладателя нельзя. При ошибке WebGL,
загрузки ассета или отсутствии моделей интерфейс использует прежний
`moose2d.js`.
  - Где данных нет — модель (`app/moose.py`), откалиброванная по реальным тестам (`tools/calibrate_moose.py`,
    ошибка ≈ 4,4 км/ч). В ответе API и в интерфейсе всегда видно: «Реальный тест» (со ссылкой) или «Оценка модели».
- API: `GET /api/v1/cars/{id}/moose?speed=60` → объезд (предел, вердикт, тип срыва) и удар (скорость удара,
  уровень нагрузки по местам: водитель / пассажир / сзади × голова / грудь / ноги).
- Анимация — 2D Canvas (`app/static/js/moose2d.js`): вид сверху для объезда (лось резко выпрыгивает из кустов,
  следы шин, спидометр, индикатор крена, замедленная съёмка), вид сбоку в разрезе для удара — манекены,
  подушки, трещины стекла, продавленная крыша; после удара зоны манекенов окрашены по тяжести.
- Тесты: `tests/test_moose.py` (реальные данные используются, провал RAV4 отражён, быстрее — не легче и т. д.).

### 3D (`app/static/js/viewer.js`)
- Модель `static/media/models/lada_vesta_parts.glb` разбита на 38 деталей; их описание —
  `lada_vesta_parts.json` (id, `label_ru`, `group`: exterior/interior, узлы GLB, bbox, anchor, статус).
- Связка с БД: `cars.model_key` → GLB, `cars.parts_key` → parts.json, `cars.hotspots` → `{id детали: факт об этой машине}`.
  Подсказка = название детали из parts.json + факт из БД («Рычаг коробки передач — Коробка: механика»).
- Снаружи реагируют только внешние детали, из салона — только салон; деталь чужой группы перекрывает луч
  (через лобовое не подсвечивается капот, снаружи через окно — сиденья). Сквозь стёкла луч проходит.
- Кузов (материал `kuzov`) перекрашивается в цвет из описания пользователя; стёкла полупрозрачные.
- «Сесть в салон» — камера встаёт над водительским сиденьем (`seat_driver`), угол обзора 70°.
- `?debug` в URL — объект `window.viewer` для отладки из консоли.
- Новая модель: положить GLB + parts.json в `static/media/models/`, прописать ключи в сиде.

## Инспектор кода элемента (для разработки)

- `Alt+B` — режим «бэкенд», `Alt+F` — режим «фронтенд» (физические клавиши, работают в любой раскладке),
  `Esc` — выйти. Повторное нажатие той же комбинации тоже выключает режим.
- В режиме элемент под курсором подсвечивается: красный — бэкенд, зелёный — фронтенд.
  Клик фиксирует выделение и открывает карточку в левом верхнем углу: в ней показан
  **только блок выбранного режима** (бэкенд или фронтенд) с папкой, файлом и диапазоном строк.
  Переключение Alt+B/Alt+F обновляет уже открытую карточку.
- Поддержаны составные селекторы (`.level-btn > b`, `.qa-opt span`, `.chip .x`, `.block ul li` и др.), поэтому
  отдельно выделяются и мелкие элементы вроде текста кнопки, иконки, крестика или номера вопроса.
- Внутри шторки «Подробнее» размечены заголовок и мета, группы и плитки характеристик, блоки с пояснениями
  и пункты списков, ссылка на объявление, чипы, «Я понял так…», поле замечания и атрибуция модели.
  Незамеченные мелкие листья подсвечиваются серым точечно, а не «раздуваются» до всей панели.
- Карта соответствий лежит в `app/static/dev/source-map.json` и пересобирается командой
  `.venv\Scripts\python.exe tools\build_source_map.py` после изменений в коде или разметке
  (номера строк берутся из AST Python и сканирования HTML/JS, а не вручную).
- Файлы: `app/static/js/inspector.js`, `app/static/css/inspector.css`,
  генератор `tools/build_source_map.py`.
